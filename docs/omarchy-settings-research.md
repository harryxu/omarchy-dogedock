Reviewed 2026-11-16 against the installed Omarchy package, `4.5.0-3` as reported by `pacman -Q omarchy`, the upstream `v4.5.0` release, and the `quattro` branch. ## Safety rules and storage conventions

- Third-party plugins run in the Shell process with the user's file and process permissions. Omarchy scopes the QML interface it hands to plugins and protects authentication services separately. The marketplace's published findings and review capabilities do not list writes to `shell.json`. That policy describes limited static checks on specific commits. [Omarchy plugin runtime](https://github.com/omacom/omarchy/blob/v4.5.0/docs/omarchy-shell.md#installing-a-third-party-plugin) · [Marketplace security policy](https://github.com/omacom/omarchy-plugin-marketplace/blob/main/SECURITY.md#automated-security-baseline)
- Omarchy documents ordinary service and menu preferences as inline fields on their own `plugins[]` entry. The scoped facade offers `updateEntryInline(id, settings)`. For DogeDock the host writes the `harryxu.dogedock` entry and expects all the settings to keep because it rebuilds the matching entry around its ID. The service loader does not inject the entry's settings or expose the full `shellConfig` through its facade, so the write method alone does not supply a way to read the settings. [Configuration reference](https://github.com/omacom/omarchy/blob/v4.5.0/docs/omarchy-shell.md#shelljson) · [Facade source](https://github.com/omacom/omarchy/blob/v4.5.0/shell/services/PluginShellApi.qml) · [Host implementation](https://github.com/omacom/omarchy/blob/v4.5.0/shell/shell.qml)

## DogeDock's settings

- DogeDock declares `omarchy.clonedFrom: "omarchy.dock"`. Keeping position, auto-hide, and pins under `dock` matches the built-in Dock and keeps `omarchy dock` interoperable. DogeDock watches the user and packaged config files because its scoped facade omits the built-in Dock's config object. DogeDock uses Omarchy's `omarchy-dock` command for writes to these three preferences. [DogeDock manifest](../manifest.json) · [DogeDock service](../Dock.qml) · [Built-in Dock](https://github.com/omacom/omarchy/blob/v4.5.0/shell/plugins/dock/Dock.qml) · [Dock CLI](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-dock)
- Size and extension preferences are DogeDock-specific. Storing them at `dock.sizeLevel` and `dock.extensions` works with the current config reader and writer but sits outside the documented inline plugin-entry convention. The writer sources Omarchy's hidden `omarchy-shell-config` helper and passes setting values to `jq` as arguments. The helper rewrites the whole file and can normalize unrelated fields, including the version, bar layout, and plugin list. DogeDock queues its position, auto-hide, size, and extension writes, while pin writes run separately. The helper has no shared lock with the Shell's writer or other CLI invocations, so overlapping edits can lose changes. It also uses bare `mktemp` followed by `mv`. On the reviewed machine, `stat -c '%d %n' /tmp "$HOME/.config/omarchy"` showed different filesystems, so `mv` falls back to a copy for a write staged in `/tmp`. [Configuration reference](https://github.com/omacom/omarchy/blob/v4.5.0/docs/omarchy-shell.md#shelljson) · [DogeDock service](../Dock.qml) · [CLI helper](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-shell-config) · [Shell writer](https://github.com/omacom/omarchy/blob/v4.5.0/shell/shell.qml) · [GNU Coreutils `mv`](https://www.gnu.org/software/coreutils/manual/coreutils.html#mv-invocation)
- DogeDock loads external Dock extensions directly into the Shell process after reading their manifests. Enabling one runs its QML with the user's permissions. DogeDock documents this trust requirement. [Extension loader](../DockExtensions.qml) · [Extension development guide](extension-development.md) · [Trust decision](adr/0001-load-trusted-qml-extensions.md) · [Omarchy plugin runtime](https://omarchy.org/manual/shell-plugins/)

An inline DogeDock entry would follow the documented storage convention for size and extensions and use the Shell's scoped writer. That change would need a read path and migration for existing values. It would also need to account for Omarchy removing the entire `plugins[]` entry when DogeDock is disabled, since the current top-level Dock settings survive disable and re-enable. [Configuration reference](https://github.com/omacom/omarchy/blob/v4.5.0/docs/omarchy-shell.md#shelljson) · [Plugin registry](https://github.com/omacom/omarchy/blob/v4.5.0/shell/services/PluginRegistry.qml) · [DogeDock service](../Dock.qml)
